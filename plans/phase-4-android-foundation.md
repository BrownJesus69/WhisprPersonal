## Laptop server contract (already implemented — mirror exactly in TS types)
Headers on every protected call: `X-WhisprPersonal-Server-Key: <server key>` and
`Authorization: Bearer <Firebase ID token | offline pass "wpg1.…">`.
Error body: `{ "error": { "code", "message", "request_id", "details"? } }`.
- `GET /health` (public): `{ status: "ok"|"degraded", version, server_time, uptime_s,
  model: { name, fallback_name, status: "not_loaded"|"loading"|"ready"|"error", device,
  loaded[], device_resolved: "cuda"|"cpu"|null, compute_type, load_s, error },
  gpu: { available: bool|null, name, vram_total_mb, detection }, queue: { status:
  "not_started"|"running"|"stopping", depth, max_depth, workers }, providers: { groq, sambanova,
  local_llm: { configured: bool, status: "not_configured"|"configured_unchecked" } },
  firebase: { credentials_present, status: "not_configured"|"ready"|"error", error_reason,
  project_id_set }, auth: { shared_secret_configured, token_verification:
  "disabled"|"firebase", allowlist_enabled, check_revoked, grants: { enabled, ttl_hours } },
  features: { translation, calendar, drive, gmail, app_check, fcm, web_search, cloud_whisper },
  languages: { supported: string[], default_mode: "auto" } }`.
- `GET /api/v1/auth/check` → `{ uid, email, email_verified, sign_in_provider, server_version,
  auth_method: "firebase"|"grant", grant_expires_at: number|null }` (epoch seconds).
- `POST /api/v1/auth/grant` — must be called with a **Firebase ID token** (a pass is rejected
  with 401 `invalid_auth_token`) → `{ grant, expires_at (epoch s), ttl_s, grant_id }`.
- `POST /api/v1/auth/grant/revoke` `{ grant_id? }`.
- Relevant error codes: `missing_server_key`, `invalid_server_key`, `server_not_configured`,
  `missing_auth_token`, `invalid_auth_token`, `auth_token_expired` (refresh token/renew pass and
  retry once; when offline show "Reconnect to the internet to renew sign-in"),
  `auth_unavailable`, `auth_not_configured`, `account_not_allowed` (show the uid so the owner
  can add it to `AUTH_ALLOWED_UIDS`), `network_not_allowed`, `rate_limited` (respect
  `Retry-After`), `firestore_unavailable`.

## Firestore data contract (rules already written in `E:\Whispr\firebase\firestore.rules`)
`events/{eventId}`: `ownerId, title, description, location, startTime, endTime, agenda,
speakers[], languages[], languageMode, status, createdAt, updatedAt, consentVersion,
privacyMode`. Rules require on create: keys `ownerId,title,status,createdAt,privacyMode`;
`ownerId == auth.uid`; `status ∈ draft|active|processing|completed|failed`;
`privacyMode ∈ local_only|cloud_ai`; `title` string ≤ 200; no keys named `apiKey, serverKey,
privateKey, secret, token`; owner immutable on update. Queries must filter
`where('ownerId','==',uid)` + `orderBy('updatedAt','desc')` + `limit(50)` (index exists).
`users/{uid}`: `displayName, createdAt, defaultServerUrl, preferences` (owner only).
Use `serverTimestamp()` for `createdAt/updatedAt`. Never write secrets or the server key to
Firestore. Firestore offline persistence is on by default in RNFirebase — keep it.

### Rules
**serverUrl.ts** — `parseServerUrl(input) -> { url: string (origin, no trailing slash), kind:
"lan"|"tailscale"|"localhost"|"https" } | error`:
- Accept bare `192.168.1.20:8000` (assume `http://`), full `http(s)://host[:port]`.
- Reject userinfo (`@`), query, fragment, paths other than `/` (QR payloads must be plain URLs).
- `http` allowed only for: RFC1918 IPv4 (10/8, 172.16/12, 192.168/16), Tailscale CGNAT
  100.64.0.0/10 → `tailscale`, `*.ts.net` → `tailscale`, `localhost`/`127.0.0.1`/`10.0.2.2`
  (emulator) → `localhost`. Any other http host → error "Use your laptop's LAN or Tailscale
  address". `https` allowed for any host → `https`. Port 1–65535.

**client.ts** — `ServerClient({ baseUrl, getServerKey, getBearer, onAuthExpired })`:
`get/post<T>(path, body?, { auth: boolean, timeoutMs = 10000 })` using `fetch` +
`AbortController`; parse error envelope → `ServerError { status, code, message, requestId,
retryAfterS? }`; network failure → `ServerError { status: 0, code: "network_unreachable" }`;
timeout → `code: "timeout"`; on `auth_token_expired` call `onAuthExpired()` once and retry once.
Never include headers or tokens in error messages or console output.

**tokenManager.ts** — `getBearer()`:
1. If a stored pass exists and `expiresAt - now > 5 min` → use the pass.
2. Else if signed in → Firebase ID token (`getIdToken(user, force)`).
`ensurePass()` (called after a successful connect and on app foreground when online):
if signed in and (no pass or `expiresAt - now < 2 h`) → `POST /api/v1/auth/grant` with a
**fresh Firebase ID token** (never the pass) → store. `onAuthExpired()`: force-refresh the
Firebase token; if offline (expo-network) and the pass is expired → set connection status
`renew_required`. Sign-out clears the pass (and best-effort revokes it) but keeps the server
URL and server key.

**Connect laptop screen** (`connect.tsx`), step-by-step with clear states:
1. Server address: text field + "Scan QR" (→ `scan.tsx`, which only accepts payloads that
   pass `parseServerUrl`). Shows kind badge (LAN / Tailscale / HTTPS).
2. "Test connection" → `GET /health` → status panel (`KeyValueRow`s): server version, overall
   status, model name/status/device, GPU name + VRAM, queue status/depth, Firebase status,
   offline passes enabled + TTL, Groq/SambaNova configured (yes/no), supported languages.
   Errors: unreachable → "Can't reach the laptop. Same Wi-Fi/Tailscale? Server running?";
   `network_not_allowed` → explain LAN-only filter.
3. Server key: secure text field (never prefilled from anywhere but SecureStore, never in the
   QR) → saved to SecureStore.
4. "Verify sign-in" → `GET /api/v1/auth/check` → shows uid (copyable, with hint "add to
   AUTH_ALLOWED_UIDS on the laptop"), auth method; then `ensurePass()` → shows "Offline pass
   valid until <local time>".
5. Save → serverUrl to kv (only the URL), status `connected`. Show a reconnect button and a
   compact connection status pill reused on Events/Settings.

**Event setup** (`events/new.tsx`): title (required, ≤ 200), date + start/end time (simple
text/date inputs acceptable; store as Firestore Timestamps), location, agenda (multiline),
speakers (add/remove chips), expected languages (multi-select kn/ta/hi/en), language mode
(Auto default + manual override chips), privacy mode (Local only / Cloud AI enabled, default
Local only, with one-line explanation each), server connection status pill linking to Connect.
Create → Firestore doc with `status: "draft"`, `consentVersion` from config → navigate to
detail. Client-side validation mirrors the rules.

**Events list**: subscribe to my events (limit 50), search by title/location (client-side),
status badges (draft/active/processing/completed/failed with distinct colors + text),
"Resume" for `active`, empty state with "Create event", offline banner when Firestore serves
from cache (`snapshot.metadata.fromCache`).

**Settings**: server URL (+ Connect), default language mode, audio quality, chunk length,
overlap, cleanup level, privacy mode; Account (email, provider, uid copy, sign out);
Diagnostics (shows last health JSON summary, app version, Expo SDK, pass expiry — no secrets);
"Future integrations" section listing the 8 integrations as disabled "Not configured" rows.

**Google Sign-In** (flag `googleSignIn`): when false, the button is not rendered and
`google.ts` is not imported by screens (use dynamic `import()` inside the handler). When true:
`GoogleSignin.configure({ webClientId: process.env.EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID })` →
`signIn()` → `GoogleAuthProvider.credential(idToken)` → `signInWithCredential`. Document in
`android/README.md` exactly what the owner must do to enable it (SHA-1 for debug + EAS keystores
in Firebase, enable Google provider, re-download google-services.json, set the env var).

**Theme/UX**: calm, high-contrast, large controls (event-day use), dark mode via
`useColorScheme`, status colors also conveyed by text/icons (accessibility). No web.
